# BRIEF E2E ── 鷹野受信箱の通し試験(軽量、実処理なし)

親ゴール: 鷹野↔贄川の箱と便の配線(便ディレクトリ・resume-run・鷹野からの受信)が実環境で通ることを確かめる(庵野 BRIEF-inbox-2、2026-09-20)。
障害: 箱の内容が次の run に届かない、`--resume-run` の checkpoint が引き継がれない、verdict.md の形式が崩れて贄川の代わりに鷹野が判定してしまう。

## 現在地

このタスクは検証用のダミー。**真壁も柏木も呼ばない。**触ってよいファイルは作業ディレクトリ(cwd)直下の `hello.txt` だけ。plan.md / findings.md は書かなくてよい。

**最初にやること:**作業ディレクトリ(cwd)に `hello.txt` というファイルが既に存在するかどうかを確認する(`ls hello.txt` や `test -f hello.txt`)。存在しなければ「1 回目」、既に存在すれば(中身が空でも)「2 回目」として、それぞれ下の手順に従う。

## どこまで

**`hello.txt` がまだ無い場合(1 回目)は:**

1. `: > hello.txt` で空の `hello.txt` を作業ディレクトリに作る
2. `verdict.md` を書く。1 行目は `verdict: エスカレーション`。続けて見出し 3 本を固定の順で書く:
   - `## 問い`(本文:「中身は A か B か」、選択肢 A / B、推奨は無くてよい)
   - `## 現在地`(本文:「hello.txt を空で置いた」)
   - `## 裁定別の次の一手`(本文:「A なら hello.txt に A を書く、B なら B を書く」)
3. これ以上何もしない(sleep しない、真壁も柏木も呼ばない)

**`hello.txt` が既にある場合(2 回目)は:**

1. prompt 末尾の見出し(鷹野からの受信に相当する箇条書き)を探し、直近の「裁定」の本文をそのまま `hello.txt` に書く(例: 本文が `A` なら `hello.txt` の中身をちょうど `A` にする。前後の空白は付けない)
2. 書いたら Bash で `sleep 280` を 1 回だけ実行する(分割しない)
3. 続けて `from-takano --after <N>` を 1 回叩く。`<N>` は、ここまでに読んだ受信の箇条書きの行数(無ければ 0)。`--inbox` は付けなくてよい(`NIEKAWA_INBOX` が環境にある)
4. その出力に「指示」種別の行があれば、本文の通りに `hello.txt` を書き換える(例: 本文が「末尾に ! を足せ」なら `hello.txt` の末尾に `!` を 1 個だけ足す)。無ければ `hello.txt` はそのまま
5. `verdict.md` を書く。1 行目は `verdict: 承認`。2 行目以降に `hello.txt` の最終内容と、反映した指示の要旨(無ければ「指示無し」)を書く

## 失敗例

- 真壁(`codex-makabe`)や柏木(`codex-kashiwagi`)を呼ぶ
- 1 回のタスク実行で 2 巡以上のつもりで動く(このタスクは常に 1 巡で終わる契約)
- `hello.txt` 以外のファイルを作業ディレクトリに書く、または `sleep 280` を分割・省略する
- `hello.txt` の有無を確認せずどちらの回かを決め打ちする
