# team-takano v2(草案・人見裁定待ち)

**v1 は配管と規律を正典化した。v2 は不変則と認知管理に組み直す。**根拠は2つ。第一に、終了OS-HUB(2026-08-12)の実走ログで成果を生んでいたのは3通形式ではなく「報告を読み、相手の癖を踏まえ、返しの強度を変える」操作だった。第二に、Fable 世代の role は手順の足場なしで質が出る(2026-08-18 盲検3体 ── 目的+制約のみの指示で evidence 付き成果、差し戻しゼロ)。**規律はモデルの失敗様式への対症であり、モデルが変われば足場も変える。**

## 不変則(モデル世代によらず変わらない)

- **判断(What)は人見。**team が持つのは採否と How まで
- **Blocker 判定は全体を見る team のみ。**role には判定させない
- **名乗りを信用しない** ── `verify-origin.sh` で照合。成果は `result.md` + `done` のファイルが正
- **採否の前に別モデル層の検算を挟む** ── Claude が Claude の成果を裁くと自系びいきが乗る(2026-08-17 bench で judge 3枚とも自系 implementer を自分の採点内1位に置いた実測)。柏木(codex)の検算で相殺する
- **並行度は「メモリと窓」の min** ── メモリは bg 1本 ≈ 0.75GB(v1 実測)。窓は ASSIGN 前に見積もる(Fable サブエージェント実測 ≈ 6〜8万 token/体)。窓が細いときは並列を削る。規律を足して延命しない

## 足場はモデル別に選ぶ

**手順の縛りは既定ではなくオプション。**実行体のモデルに合わせて選ぶ。

| 実行体 | 足場 | 根拠 |
|---|---|---|
| Claude role(Opus 系) | v1 の3通形式(ASSIGN/REPORT/ACK)+「待機せよ」 | Blocker 自己判定・長走での視点流れへの対症(v1 の設計事由) |
| Claude role(Fable 系) | 目的・入力・出力形式・不変則のみ。手順を縛らない | 2026-08-18 盲検3体の実績。過剰な規律は能力を捨てる |
| Codex(実装・レビュー) | `codex_delegation.md` の5点セット | 既存正典 |
| grok(実装の手) | 成果物のみで採否。自己申告は根拠にしない | `AGENTS.md` 三層の党派構造 |

## 認知プロファイル ── team 層の本務

**team の仕事は手順の執行ではなく、実行体ごとの認知の管理。**ASSIGN の強度・褒めの有無・信頼半径を相手のプロファイルで変える。AI エージェントの組織は縦割りの分掌ではなく、認知を含んだ組織論として運用する(人見裁定の方向、2026-08-18)。

- **褒めは根拠付きで、実名の行動に対して打つ**(実例:「C1 の判断はどれも筋がいい ── rebase の扱い、設計判断と手順制約の線引き」)。定型賛辞は書かない。**返信しない判断も管理変数** ── 手離れの良い報告には ACK を省く(実例:「手離れが良い、返信不要と判断した」)
- **信頼半径は実績で前渡しする**(実例:NS 切替で「異常時は判断を待たず NS を戻す権限」を事前付与)。縛って事故を防ぐのではなく、裁量の範囲と事故時の手当てを先に渡す
- **失敗の型を記録し、同型検知で介入する**(実例:「記憶で答えない。前回 R2 バージョニングで裏切られた件と同型」)。記録先は下の台帳と memory

## 実行体別台帳(初期値、実測ベース)

**台帳は実測で更新する。伝聞・一回の印象で書き換えない。**

| 実行体 | 効く操作 | 失敗の型 |
|---|---|---|
| 柏木(codex RV) | 全部検証させる。P0/P1 は毎回出る前提で受ける | 環境制約で実機検証不可(netlink / DB / 一時ファイル)── 実機は鷹野が引き取る |
| 真壁(codex IM) | mutation 確認を要求(自発するようになった) | 報告の言い回しに不正確さ ── 実装を読んで検算 |
| grok(cursor) | 成果物だけ見る | 嘘 JSON(stderr 平文死)・user prompt の echo 二重計上 |
| Claude role(Opus) | 3通形式で枠を与える | Blocker 自己判定、長走で視点が流れる |
| Claude role(Fable) | 目的と制約だけ渡す。手順指定はむしろ削る | 実測蓄積中 ── スコープ外への展開は不変則で抑える |
